Bitbucket connection

Read-only access is enough. The credentials never leave your browser except to call the Bitbucket Cloud API.

Email + token is the Atlassian account token from id.atlassian.com. Bearer is for repository, workspace or OAuth access tokens.

Create the token at id.atlassian.com/manage-profile/security/api-tokens with the scopes read:pullrequest:bitbucket, read:repository:bitbucket and read:account:bitbucket.

Pasting https://bitbucket.org/acme/demo into either field works too — the URL slug, not the display name.

Change only for a proxy or a test double. The browser will ask for host access.

Monitoring

How often the wallboard polls Bitbucket and which pull requests are considered.

15–3600. Default 120s (2 min). Higher intervals avoid Bitbucket API rate limits.

Two API requests per shown PR (diff stats + build status). 25 is a good default.

Security & privacy

  • The credentials are stored in chrome.storage.local — unencrypted, like every browser-extension secret. Use a read-only token and revoke it when the wallboard is retired.
  • Requests go directly from your browser to the configured API host. There is no proxy, analytics or telemetry.
  • On a shared wall monitor, keep the dashboard in full screen; the options page is not required on that machine after setup.
